PJT Rallye

An interactive event platform for the Pfingstjugendtreffen in Aidlingen. A mobile player app, a backend for sessions and quest progress, and an admin interface for running the rally.

video
01 — A closer lookRecorded from the working website

The rally doesn't stop at the interface.

Participants need to join quickly, follow quests and retain their progress when the connection drops. Organisers need a separate view of the event: editable quests, badges, announcements and activity.

One event.
Connected parts.

01 / Player

Play & save

Quest state and answers are stored locally. A retry queue syncs answers when the connection returns.

↔
02 / API

Coordinate

A Node.js API handles recovery sessions, submissions, quest configuration and badge progress.

↔
03 / Data

Persist

PostgreSQL stores shared state. Redis supports caching; object storage serves admin assets and feedback uploads.

Admin → API

Quest editing, player management, announcements and analytics use the same backend. Player quest photos remain on the participant's device — only completion is synchronised.

Start simply.
Recover reliably.

A nickname starts a session; a recovery code restores it without email or a password. The interface keeps quests, progress and badges close at hand.

An application, not a static site.

The project connects the player experience with event administration, data flows and a container-based deployment setup. Retry logic, session recovery, request limits and analytics caching are part of the implementation — not just the visual layer.

This selection shows the entry and recovery interface. No participant accounts, personal photos or live event data are shown.
